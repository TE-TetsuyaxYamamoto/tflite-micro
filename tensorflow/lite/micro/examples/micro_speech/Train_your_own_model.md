# Train Your Own Micro Speech Model

この文書では、既存の `yes` / `no` モデルを使う代わりに、独自のキーワードを認識する Micro Speech モデルを学習し、TensorFlow Lite Micro (TFLM) で実行するまでの流れを説明します。

## 1. 学習で作るもの

Micro Speech は、音声を直接分類するのではなく、音声から作ったスペクトログラム特徴量を分類する小型モデルです。

```text
WAV 音声
    ↓
音声前処理
    ↓
スペクトログラム特徴量
    ↓
小型ニューラルネットワーク
    ↓
silence / unknown / キーワード
```

既存モデルの出力カテゴリは、通常次の4種類です。

- `silence`: 無音
- `unknown`: 対象外の音声
- `yes`: キーワード `yes`
- `no`: キーワード `no`

再学習すれば、`yes` / `no` の代わりに、例えば `up` / `down` や `start` / `cancel` を認識させられます。

## 2. 学習方法

学習用 Notebook は次のファイルです。

```text
tensorflow/lite/micro/examples/micro_speech/train/train_micro_speech_model.ipynb
```

README では、次の2つの実行方法が紹介されています。

### Google Colaboratory

GitHub 上の Notebook を Google Colab で開いて実行します。TensorFlow の環境構築を自分で行う必要が少なく、学習用の計算資源も利用できるため、最初に試す方法として適しています。

### ローカル Jupyter Notebook

Notebook をダウンロードして、自分の PC 上で実行します。ただし、元の README は古い環境を前提としており、TensorFlow 1.5、Python 3.7 と記載されています。現在の Python や TensorFlow では互換性の問題が出る可能性があるため、Notebook の依存関係を確認してください。

README に記載されている学習時間の目安は約2時間ですが、データセット、CPU/GPU、実行環境によって変わります。

## 3. データセット

既存の例では Speech Commands Dataset Version 2 を使用します。このデータセットには、複数の話者が発音した多数の単語の WAV ファイルが含まれています。

```text
Speech Commands Dataset Version 2
```

データセットを使う利点は、単一の話者や録音環境に依存しないモデルを作りやすいことです。一方で、アーカイブは大きく、README では2 GB以上と説明されています。

### 独自キーワードを使う場合

データセットにない単語を認識させる場合は、自分で音声を録音する必要があります。対象キーワードだけでなく、次のデータも用意します。

```text
対象キーワード:
  start
  cancel

対象外:
  hello、stop、通常の会話など

無音:
  無音、または環境音だけの録音
```

必要なデータは、学習用、検証用、テスト用に分割します。できれば複数の話者、異なる声量、マイクとの距離、背景ノイズ、部屋の違いを含めてください。

対象キーワードだけを学習させると、関係のない音声やノイズまでキーワードとして判定しやすくなります。`unknown` と `silence` のデータは、実用上重要です。

## 4. 音声入力の条件

既存の Micro Speech 例では、音声を次の形式にそろえます。

- サンプリング周波数: 16 kHz
- チャンネル数: 1、モノラル
- サンプル形式: 16-bit PCM
- 音声長: 約1000 ms

学習時と推論時で音声前処理の条件を一致させる必要があります。

## 5. スペクトログラム前処理

モデルは生の音声波形を直接入力しません。音声を時間ごとの周波数情報へ変換します。

既存の設定では、次の処理を行います。

- 30 ms の音声窓を作る
- 20 ms ずつ窓を移動する
- 隣り合う窓を10 ms重ねる
- 各窓に FFT を適用する
- 周波数情報を40個の周波数バケットへ集約する
- スケール変換、ノイズ低減、自動ゲイン制御を行う

1000 ms の音声からは、およそ49個の時間フレームを作れます。したがって、モデル入力は概念的に次の形になります。

```text
49 frames × 40 frequency buckets
```

これは、横幅40、縦49の1チャンネル画像に近いデータです。

学習時と実機上の前処理が異なると、学習時の精度が高くても実機で認識できません。TFLM で使用する場合は、既存の `Audio Preprocessor` と同じ前処理設定を使ってください。

## 6. モデル構造

Micro Speech のモデルは、マイコンで動かせるように小さく設計されています。基本構造は次のとおりです。

```text
スペクトログラム入力
    ↓
Convolution 2D
    ↓
Fully Connected または MatMul
    ↓
Logits
    ↓
Softmax
    ↓
カテゴリ確率
```

例えば、出力が次のような場合を考えます。

```text
[silence=0.01, unknown=0.03, up=0.92, down=0.04]
```

最も確率の高い `up` を認識結果として扱います。

このモデルは、大規模な音声認識システムの代わりではありません。常時起動する低消費電力デバイスでキーワードを検出し、必要なときだけ高性能なプロセッサを起動する、第1段階の検出器として使うことを想定しています。

## 7. 学習後に作られるモデル

学習用 Notebook では、用途に応じて次の形式のモデルを作成します。

| ファイル | 形式 | 用途 |
| --- | --- | --- |
| `model.pb` | Frozen GraphDef | TensorFlow のグラフ確認 |
| `model.tflite` | 量子化 TensorFlow Lite モデル | TensorFlow Lite / TFLM の入力 |
| `model.cc` | C/C++ ソース配列 | マイコンのファームウェアへの組み込み |

最終的に TFLM で使用するのは、通常 `model.tflite` を C++ 配列へ変換したものです。

## 8. 量子化

量子化は、`float32` の重みやテンソルを `int8` などの小さい整数型で表現する処理です。

```text
float32: 1値あたり4バイト
int8:    1値あたり1バイト
```

`int8` 量子化には、次の利点があります。

- モデルサイズを小さくできる
- RAM 使用量を抑えやすい
- 整数演算対応のマイコンで高速に動作しやすい
- 消費電力を抑えやすい

README の `fully quantized` は、重みだけでなく、入力と出力も含めて厳密に `int8` であることを意味します。量子化後は、`float32` モデルと比べて認識精度が大きく低下していないか確認してください。

## 9. 学習後の検証

学習が終わったら、次の順番で確認します。

### 学習データと検証データ

学習データだけでなく、学習に使っていない検証データでも精度を確認します。学習データでは高精度なのに検証データで低精度の場合は、過学習の可能性があります。

### 量子化後のモデル

`float32` の結果と `int8` の結果を比較します。TFLM で使うのは最終的に量子化されたモデルなので、量子化後の精度を重視します。

### TFLM 上の推論

PC 上の TFLM テスト、QEMU、対象マイコンの順に確認します。最低限、次の項目を確認してください。

- モデルを正常に読み込める
- 入力 Tensor の型が一致する
- 入力形状が一致する
- 出力カテゴリ数が一致する
- Tensor Arena の容量が足りている
- キーワード、`unknown`、`silence` を適切に判定できる

モデルが20 kB未満でも、実行時には Tensor Arena、音声バッファ、プログラム本体などのメモリが必要です。

```text
必要メモリ = モデルデータ + Tensor Arena + 音声バッファ + プログラム本体 + その他のバッファ
```

## 10. TFLite モデルを C++ 配列へ変換する

学習後に `model.tflite` が得られたら、`generate_cc_arrays` を使って C++ ソースへ変換します。

```bash
bazel build tensorflow/lite/micro/tools:generate_cc_arrays
```

```bash
bazel-bin/tensorflow/lite/micro/tools/generate_cc_arrays \
  /tmp/custom_model.cc \
  model.tflite
```

コマンドの形式は次のとおりです。

```text
generate_cc_arrays [出力ファイル] [入力ファイル]
```

生成された `/tmp/custom_model.cc` には、モデルのバイト列を表す C++ 配列が含まれます。生成後は、配列名やサイズ変数をファイル内で確認してください。

```bash
head -n 20 /tmp/custom_model.cc
```

## 11. TFLM プロジェクトへ組み込む

生成した `.cc` ファイルをプロジェクトへ追加し、`BUILD` ファイルの対象にも含めます。C++ コードからモデル配列を参照し、`MicroInterpreter` へ渡します。

概念的には次のような流れです。

```text
train_micro_speech_model.ipynb
    ↓
model.tflite
    ↓
generate_cc_arrays
    ↓
custom_model.cc
    ↓
BUILD に追加
    ↓
MicroInterpreter で使用
```

既存のモデルを置き換える場合は、モデルファイルだけでなく、次のコードも確認します。

- カテゴリ名の配列
- 出力インデックスとラベルの対応
- テストの期待値
- 入力形状
- 入力と出力の量子化パラメータ
- Tensor Arena のサイズ

例えば、`yes` / `no` 用のラベル配列を `up` / `down` 用に変更する必要があります。

カテゴリを増やした場合は、出力 Tensor のサイズ、最終層、ラベル配列、テストコードも一致させます。

## 12. 作業手順のまとめ

1. `train_micro_speech_model.ipynb` を Colab またはローカル Jupyter で開く
2. Speech Commands Dataset または独自の音声データを準備する
3. 音声を16 kHz、モノラル、16-bit PCM、約1秒にそろえる
4. Notebook の前処理、学習、評価のセルを順番に実行する
5. 入力と出力を含む `int8` 量子化モデルを生成する
6. `model.tflite` の入力形状、型、出力カテゴリ数を確認する
7. `generate_cc_arrays` で C++ 配列へ変換する
8. 生成した `.cc` ファイルを TFLM の BUILD と C++ コードへ追加する
9. PC、QEMU、対象マイコンの順で推論を検証する

## 13. 注意点

### 学習と推論の前処理を一致させる

前処理の窓長、ストライド、サンプリング周波数、周波数バケット数などが一致している必要があります。

### `unknown` と `silence` を用意する

キーワードの音声だけで学習すると、通常の会話やノイズもキーワードとして認識しやすくなります。

### 録音環境を多様にする

話者、発音、声量、マイクとの距離、背景ノイズ、部屋を変えたデータを含めると、実際の使用環境で安定しやすくなります。

### モデルサイズと RAM を別々に確認する

モデルが小さくても、Tensor Arena や音声バッファが大きい場合があります。フラッシュ容量と RAM の両方を確認してください。

### README のバージョン情報を確認する

学習用 README は古い TensorFlow と Python の環境を前提としている可能性があります。ローカル環境で問題が出る場合は、指定バージョンの仮想環境を用意するか、Colab で Notebook を実行してください。

## まとめ

独自の Micro Speech モデルを作る手順は、次の一連の作業です。

```text
音声データを集める
    ↓
同じ前処理で特徴量を作る
    ↓
小型モデルを学習する
    ↓
int8 TFLite モデルへ変換する
    ↓
C++ 配列へ変換する
    ↓
TFLM の MicroInterpreter へ組み込む
    ↓
実機でキーワード認識を確認する
```

この方法で、既存の `yes` / `no` モデルを別のキーワードへ置き換えたり、複数のキーワードを認識する低消費電力の音声検出器を作ったりできます。
